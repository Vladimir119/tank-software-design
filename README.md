# Tanks

Нужен JDK 17. Запуск из корня проекта:

```shell
./gradlew run
```

Windows: `gradlew.bat run`. В IDE — Gradle → application → run.
Управление: стрелки или WASD. Деревья и границы поля блокируют движение.

## Задание 1

Выделены Tank, Tree, Field и Direction. Проверка движения общая для всех
направлений, состояние танка хранится отдельно от его текстуры.

## Задание 2

Модели не зависят от LibGDX. GameRenderer, TankRenderer и TreeRenderer отвечают
за графику. KeyboardController получает источник нажатий и привязки действий;
новую команду можно добавить через bind. Launcher связывает компоненты.

Проверка: `./gradlew test` (Windows: `gradlew.bat test`).

## Задание 3

Tank зависит от MovementPolicy, GameSession — от ControlStrategy и GameView,
а приложение получает LevelSource. Правила перемещения, ввод, представление
и источник уровня можно заменять без изменения игрового цикла. Длительность
шага и пути ресурсов передаются в конструкторы. Тесты используют простые
подстановки интерфейсов и не открывают окно.

## Задание 4

По умолчанию создаётся случайное поле 10 × 8 с 18 деревьями и свободной
случайной позицией танка. Для повторяемого результата можно задать seed:

```shell
./gradlew run --args="--random --seed=42 --trees=18"
./gradlew run --args="--level=src/main/resources/levels/demo.txt"
```

На Windows используйте `gradlew.bat` вместо `./gradlew`.

Файл уровня — прямоугольник произвольного размера в UTF-8. `T` обозначает
дерево, `X` — единственную стартовую клетку, `_` или пробел — пустую клетку.
Первая строка файла соответствует верхнему ряду на экране. Например:

```text
T___
_X_T
____
```

Пустой файл, разные длины строк, неизвестные символы, отсутствие или несколько
стартов дают ошибку с описанием причины. Случайные деревья не повторяются
и не занимают стартовую клетку. Рендерер подгоняет поле под размер окна.

Полная проверка: `./gradlew clean test build`.
